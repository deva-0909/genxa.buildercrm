# Builder CRM — GENXA

Real estate lead-to-possession CRM, built from the Figma Make design "Builder CRM" and backed by Supabase.
Every screen reads and writes live data; the database enforces the business rules.

## Stack
- React 18 + Vite 6 + Tailwind CSS 4, Recharts
- Supabase (Postgres, Realtime, Storage, Edge Functions) — project `genxa-buildercrm` (ap-south-1, Mumbai)
- Hosted on Vercel (project `genxa.buildercrm`)

## Demo mode (no login)
There is no sign-in. The **Viewing as** menu switches between Admin, each staff member, a channel partner
(partner portal) and a buyer (buyer portal); each sees only what that role would. Every request carries the
chosen name in an `x-actor` header, so the audit trail records who did what.

> Anyone with the URL can read and change the data. Use sample data only. Before real customer data goes in,
> add Supabase Auth (staff email login, buyer/partner OTP) and replace the `demo_anon_*` policies with
> role-based row-level security.

## What the database does
- **IDs** are generated by the database (`LD3245`, `BK166`, `RCPT/1143` …), so two people saving at once never collide.
- **Leads:** mobile must be a valid 10-digit Indian number (normalised), email checked, duplicates of any open lead blocked.
- **Visits** can't be scheduled in the past.
- **Inventory:** 472 units across towers and floors. Booking or blocking a unit updates its status; a booked unit can't be
  booked or blocked again; blocks expire automatically; booked units' prices are locked.
- **Bookings** create the construction-linked payment schedule (from the project's stages), the token receipt, a draft
  agreement with stamp duty and registration, and a discount approval when the discount is above the limit (2%).
- **Payments ledger:** receipts are allocated to instalments oldest-first; statuses (Due / Overdue / Paid) and the
  booking's paid total are recomputed; GST at 1% (≤ ₹45 L) or 5%.
- **Construction stages:** marking a stage complete raises that instalment for every booking in the project, due in 15 days,
  and queues demand letters. Late interest accrues at the configured rate.
- **Loans:** each disbursement posts a Home Loan receipt.
- **Agreements:** signing moves the booking to Agreement Done; e-signatures are stored in Storage.
- **Cancellations:** 10% / 20% / 25% deduction by age, approval required; approval cancels the booking, frees the unit and
  closes the lead; refund posts a refund voucher.
- **Audit trail** on every table; **daily refresh** (`refresh_demo_dates`) moves demo dates to today, expires blocks and
  flags overdue instalments — run automatically when the app opens.

## Integrations
- **Lead intake API** (Edge Function `lead-intake`): `POST https://tvrveybyoiqtikbycgzl.supabase.co/functions/v1/lead-intake`
  with header `x-intake-token` (value in Master Setup → Rules & integrations). Accepts website JSON, Google Ads lead-form
  webhooks and Meta lead ads (`field_data`, plus the webhook verification handshake). Duplicates become a re-enquiry note
  on the existing lead; new leads are assigned to the least-loaded telecaller with an in-app alert.
- **WhatsApp / calls:** click-to-chat (`wa.me`) and click-to-call (`tel:`) everywhere, each logged. For automatic sending,
  connect a WhatsApp Business API provider and a cloud telephony account (Exotel/Knowlarity) via an Edge Function; keep
  their keys in Supabase secrets, never in the browser.
- **Tally:** Payments → Export to Tally produces a voucher XML (Gateway → Import Data → Vouchers).
